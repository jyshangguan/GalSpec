Fitting a real spectrum 13.3&times; faster on one GPU than on 16 CPU cores

OverviewThe modelResultsGlossary

We fitted a real optical spectrum of a galaxy with a physically motivated model of 21 numbers, several times over: with the existing CPU code path and with the new GPU code path, each using all the nested sampling machinery it has. The model and the data are identical in every run. The GPU finished in 6.3 min; 16 CPU cores needed 83.7 min (13.3× faster), and a single core needed 8.9 h (84.7× faster).

The short version

  • What we fit: one spectrum of the quasar IRAS 07546+3928 from the Sloan Digital Sky Survey (SDSS), a public survey. The spectrum covers 59,146 pixels (wavelength 4200–6900 Å).
  • The model: a smooth continuum + iron emission + 11 emission lines. The three hydrogen lines are each split into a narrow (slow gas) and a broad (fast gas) component; the forbidden lines get a narrow component, with a broad wing added for [O III] — 21 free numbers in total.
  • Two samplers: nested sampling explores the posterior — it maps out which parameter values are plausible. The existing code uses dynesty with astropy models on the CPU; the new code uses JNesty with jax models, which can run on the gpu.
  • Same stopping rule: both stop when the remaining uncertainty in the logz (evidence) is below 0.01 — the "dlogz" criterion. The answer is therefore not a premature one.
  • Result: the two paths find the same fit. Every one of the 21 numbers agrees to better than 0.1 of its own error bar; reduced χ² is identical. The evidence differs slightly between samplers, and so does it between two runs of the same sampler — see the results page for what that does and does not mean.

"Likelihood calls" is how many times the model was compared with the data. Each sampler counts its own calls, and a call costs one model evaluation; the two columns are therefore indicative rather than identical, because the samplers decide differently how many proposals to try before accepting a point. The wall clock in the first column is what matters.

What this does and does not show

  • It shows that the same scientific answer comes out, and that it comes out much faster on the GPU.
  • It does not show that the GPU makes every fit 20× faster. The gain grows with the size of the model: a small window around one line gains ~4–6×, because then the sampler's own bookkeeping, not the model, is the bottleneck.
  • The GPU is used as a single device; the CPU comparison also gives the "all 16 cores" number, so the comparison is fair in both directions.

Reproducing it

Everything on these pages comes from three commands (run from the repository root): 

python develop/dev_jax/run_sdss_fit.py --config jnesty-gpu       --nlive 400 --dlogz 0.01
python develop/dev_jax/run_sdss_fit.py --config dynesty-serial   --nlive 400 --dlogz 0.01
python develop/dev_jax/run_sdss_fit.py --config dynesty-parallel --processes 16 --nlive 400 --dlogz 0.01
python develop/dev_jax/make_report.py

The model itself lives in develop/dev_jax/sdss_agn.py; running that file on its own prints every prior and checks that the CPU and GPU models agree. The fit is not seeded from a previous solution: both samplers start from the priors alone.
