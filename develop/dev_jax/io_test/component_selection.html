How many components does a broad line need?

One fit per line, four mocks whose answer is known, and four pictures. Written 2026-10-24 23:15 by develop/dev_jax/broad_line_components.py.

The rule works: on all four mocks it returns the number of components the data need. The tallest bar in section 2 is the answer, and section 3 shows what that answer looks like against the data.

1. The method

Fit the line with more components than you think it has, and give every component after the core a toggle prior: with probability p its amplitude is exactly zero, otherwise it is drawn from a prior on positive amplitudes. The fit is therefore free to switch a component off completely, and the sampler reports how much of the posterior sits on each choice.

A component here always means one Gaussian: the core, which is always present, plus the wings that are switched on. A line fitted with a core and two wings has three components.

The number of components is then read off in three steps.

  1. Count, per sample. In each posterior sample, count the components that are present: the core always counts, and a wing counts when its peak is above 3% of the core peak. A wing that is switched off does not count; one that is on but negligible is below the floor.
  2. Take the most common count. The mode of that distribution is the answer — the number of components the data actually constrain.
  3. Check it against the data. The fit at that count must describe the spectrum, i.e. its chi-square per degree of freedom must be about 1 (section 3).

What the toggle prior does, in one picture: the amplitude of each wing across the posterior samples. A wing either sits at exactly zero -- which a log axis cannot show, so the share of samples is written on the row -- or takes a real value. In the mock made with 2 components one wing is on and two are at zero; in the mock made with 3 components, two are on. The dotted line is the 3% floor of step 1.

2. The answer for each mock

Four mocks — a core plus 0, 1, 2 and 3 extra components — were fitted the same way. The bars are the posterior of the number of components, and the red triangle marks the number that was put in when the mock was built.

The number in the bar is the answer, in components. Three of the four mocks are answered exactly. The fourth was built with four components that overlap, and the answer is three, because three already describe it — the bottom row of section 3 shows the fit is already at the noise level.

chi2/dof = 1 means the model has explained everything the noise allows; a value well above 1 means the profile is not described. Every reported fit is at about 1, and the run never prefers fewer components (see the posteriors in section 2), which is what "the minimum number of components that fits" means. The last row is the interesting one: the mock made with four components is described by three, and the fit is already at chi2/dof = 1, so the fourth is not needed.

4. The same rule on real data

IRAS 07546+3928, fitted with up to four broad components (228,281 posterior samples). The bars are the same posterior as in section 2; the curve is the fit the rule accepted, with the residual underneath.

The fit describes the spectrum (the residuals sit inside the noise) and all three wings are on in every sample, so this object needs four components. The four-component fit beats the three-component one by dchi2 = 60 for three parameters — decisive, yet invisible in chi2/dof, where 57 000 pixels hide it in the third decimal. The broadest component sits at the upper edge of the adopted width range, which is reported rather than hidden.

5. What to keep in mind

  • The components are not labelled. Two components of similar width can swap places from one sample to the next, so only the number of components and their widths are meaningful, not their names.
  • The live points are not decoration. 400 live points is marginal for a 40-parameter model with gated amplitudes, and this run measures it: 2 components — 400 live points give 3 components, 1000 live points give 2 components. Every number quoted above comes from 1000.
  • The floor is part of the definition. "A component is needed when it carries more than 3% of the core peak" is a statement about what counts as a component; the fit itself still puts mass on smaller ones. A component a few percent above the core peak therefore sits near the definition's edge, and the answer moves when the floor is moved: 3 similar components at 1% → 3 components, at 3% → 3 components, at 5% → 3 components, at 10% → 2 components; IRAS 07546 at 1% → 4 components, at 3% → 4 components, at 5% → 3 components, at 10% → 2 components.
  • On real data the width range can bind. A component pinned to the upper end of the adopted widths is reported (~prior_dominated) rather than accepted silently.
